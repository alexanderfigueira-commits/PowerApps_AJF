## Week 1 – Extra scenarios (requestors)

- [ ] A request with three or more media files of the same production type
- [ ] "Archive only" ticked, then submitted: the request reaches Processing
- [ ] "Copy from previous media file" used (only files of the same production type are listed)
- [ ] A draft saved, closed, reopened and completed
- [ ] Mandatory fields and attachments left empty: each message on the Validations tab is clear
- [ ] Texts of 255 characters and special characters (é, ü, €, quotes)
- [ ] Attachments: legal annexes; Video subtitles (.vtt, not .srt); Podcast visual (square, 1400 to 3000 px), episode visual (1280 x 720) and audio files
- [ ] AI-generated images or AI voice-over declared: the app reacts as expected
- [ ] Print and export screens opened for each production type
- [ ] Review day: a Pending request edited and resubmitted; a Rejected request opens read-only; an Approved one shows its Beluga reference
- [ ] Two submitted requests left untouched until week 2, to trigger the seven-day reminders

## Week 2 – Administrator checklist (all e-mails on)

- [ ] Approve a request with all media files ticked; add the Beluga reference afterwards
- [ ] Approve with only some media files ticked
- [ ] Approve an "Archive only" request with a reason in the note
- [ ] Reject a request with a reason
- [ ] Put a request on Pending with a question; the requestor answers and resubmits
- [ ] Set the assignee and the co-assignee, then change them
- [ ] Write notes as administrator and as requestor; check the unread number, the read receipt and the last-message tooltip
- [ ] An administrator who is not the creator opens the request: view-only

## Week 2 – E-mail checks

For each e-mail tick it when it arrives, and check the recipients, the text and that the link opens the request. The support mailbox is always among the recipients.

## How to report an issue

Write one line per issue in [issue log link]: request number, screen, what you did, what you expected, what happened, a screenshot. Start the title of every test request with "TEST –" so the data can be cleaned up afterwards.
